# edgeX 하이브리드 트레이딩 시스템 구축 로드맵 (Claude Code 개발 가이드)

본 문서는 edgeX 플랫폼 기반의 알고리즘 트레이딩 시스템 구축을 위한 순차적 구현 가이드라인입니다. Claude Code는 아래 순서에 따라 단계별로 독립된 모듈(파일)을 생성하고 유닛 테스트를 진행하며 시스템을 완성해야 합니다.

---

## 1. 프로젝트 개요 및 아키텍처
본 시스템은 두 개의 엔진과 자금 관리 모듈로 구성된 하이브리드 트레이딩 시스템입니다.
- **엔진 A (공격형):** 총 시드의 20~30% 운용. 박스권 횡보 매매를 수행하다가, 거래량 급증(평균의 3배 이상) 감지 시 기존 주문을 전량 취소하고 추세 돌파 매매로 전환.
- **엔진 B (수비형):** 총 시드의 70~80% 운용. edgeX 1배 숏 + 바이낸스 현물 1배 롱을 통해 가격 변동 리스크를 헷징(Delta Neutral)하고 펀딩비 수익 수취.
- **수익 스위프(Sweep):** 엔진 A의 수익금을 정기적으로 엔진 B로 이체하여 복리 증식.
- **데이터 이탈 모니터:** 시장 변동성 변화를 감지하여 알림 및 전략 수동/자동 조정 트리거 제공.

## 2. 기술 스택 및 폴더 구조
- **언어:** Python 3.10+
- **주요 라이브러리:** `web3`, `websockets`, `requests`, `pandas`, `python-dotenv`
- **폴더 구조 목표:**
  ```text
  ├── .env.example
  ├── main.py
  ├── requirements.txt
  ├── src/
  │   ├── auth.py          # 지갑 연동 및 EIP-712 서명
  │   ├── data_fetcher.py  # 실시간 시세, 거래량, 펀딩비 수집
  │   ├── engine_a.py      # 박스권 및 거래량 돌파 매매 로직
  │   ├── engine_b.py      # 펀딩비 차익거래 로직
  │   ├── sweeper.py       # 자금 스위프 및 온체인 이체
  │   └── monitor.py       # 데이터 이탈(Drift) 감지기
  └── tests/
      └── test_api.py      # 테스트넷 연동 검증 스크립트
  ```

## 3. 모듈별 역할 요약

### `src/auth.py`
- 개인 키 로딩 및 Web3 지갑 연결
- edgeX REST API용 EIP-712 서명 생성 (논스, 타임스탬프 관리)

### `src/data_fetcher.py`
- edgeX WebSocket으로 실시간 가격/거래량 스트림 수신
- 바이낸스 REST/WebSocket으로 현물 가격 및 펀딩비 폴링
- pandas DataFrame으로 OHLCV 캔들 및 이동평균 거래량 관리

### `src/engine_a.py`
- 박스권(저항/지지) 계산: 최근 N캔들 고/저 기반
- 박스권 내 그리드/리밋 주문 배치
- 거래량 spike 감지 → 기존 주문 일괄 취소 → 돌파 방향 추세 추격 주문

### `src/engine_b.py`
- edgeX perpetual 1배 숏 포지션 진입/관리
- 바이낸스 현물 1배 롱 진입/관리
- 펀딩비 수령 시각 트래킹 및 포지션 리밸런싱

### `src/sweeper.py`
- 엔진 A 실현 PnL 조회
- 설정된 임계값(SWEEP_THRESHOLD) 초과 시 엔진 B 지갑으로 온체인 이체
- 스위프 이력 로그

### `src/monitor.py`
- ATR/볼린저밴드 기반 변동성 기준값 설정
- 현재 변동성이 기준 대비 설정 배수 초과 시 DRIFT 이벤트 발행
- 콜백 핸들러 등록 인터페이스 제공

### `main.py`
- 전체 시스템 초기화 및 이벤트 루프
- 엔진 A/B 비동기 태스크 스케줄링
- 모니터 이벤트 → 전략 전환 핸들러 연결
