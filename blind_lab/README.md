# 블라인드 차트 라벨링 (blind_lab)

매매 판단력 연습 + 트레이딩 의사결정을 태그/기록으로 남겨 추후 `src/signalEngine.js` 등
규칙 기반 전략으로 패턴화할 수 있는 원재료를 모으기 위한 도구. 실데이터(edgeX)에서
미래를 가린 채 캔들을 한 개씩 공개하며, 매수/매도/관망/추가/부분정리 등 실제 트레이딩과
동일한 의사결정을 강제한다.

한 케이스(차트)당 정산 구간(60봉)이 끝나기 전까지는, 포지션을 완전히 정리해도 케이스가
끝나지 않고 같은 차트에서 다시 진입할 수 있다. 정산 구간이 끝나야(또는 끝까지 관망해야)
그 케이스가 완전히 종료되고 다음 차트로 넘어간다. 각 진입~청산 라운드는 별도 기록으로
`decisions.json`에 누적된다.

## 최초 1회 설정 (로컬)

```
cd blind_lab
node fetch_data.mjs        # edgeX 거래량 상위 종목 OHLC(30m/4h/1d) 다운로드 -> raw_data/
node prepare_cases.mjs     # raw_data에서 무작위 (종목, 시점) 60개 케이스 생성 -> cases.json
node server.mjs            # http://localhost:8731
```

`raw_data/`, `cases.json`, `decisions.json`은 용량이 크고 사용자마다 다른 데이터라 git에
커밋하지 않는다(`.gitignore` 처리됨). 코드만 git으로 관리한다.

## 코드 업데이트 받는 법

이전에는 수정할 때마다 zip을 새로 받아 덮어써야 했음. 이제는 코드가 이 저장소에 있으므로:

```
git pull
```

만 하면 됨. `raw_data/`, `cases.json`, `decisions.json`은 git이 건드리지 않으므로
기존에 쌓아온 결정 기록이나 케이스셋이 사라지지 않는다.

## 차트 풀을 다양화/최신화하고 싶을 때

```
node fetch_data.mjs [N]    # 거래량 상위 N개 종목으로 다시 받기 (기본 30)
node prepare_cases.mjs     # 새 raw_data 기준으로 케이스 60개 재추출 (실행마다 다른 무작위 시드)
```

서버를 재시작해야 새 cases.json이 반영된다. 기존 `decisions.json`은 이전 케이스셋의
`order` 번호 기준이라 새 케이스셋과 맞지 않으니, 분석 시 혼동되지 않게 별도 백업 후
초기화하는 것을 권장.

## 분석

```
node analyze.mjs           # decisions.json 누적 후 그룹/태그/타임프레임별 승률·평균수익률 집계
```

## 데이터 제약

- 30m/4h: 거래량 상위 최대 30개 종목까지 시도, 실제로는 상장 이후 데이터가 충분한
  종목만 포함된다(`fetch_data.mjs` 콘솔 로그의 "데이터 부족" 항목 참고).
- 1d: 365봉 이상 필요(워밍업 105 + 표시 200 + 정산 60)라서 최근 상장된 종목은 대부분
  제외되고 실사용 가능 종목이 10~15개 수준으로 적다. 거래소 자체에 더 긴 일봉 히스토리가
  쌓이기 전까지는 구조적 한계.
